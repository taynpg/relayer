### 1. Setting 对话框（beb6d63）

- 对照 v1 `Gui/Form/Setting` 重写，`ConnectorControl::btnLock` 解禁（模态 exec，
  纯配置操作不占传输通道，不受 HANDOFF"别模态"警告约束——那条是说任务表单）。
- **关键取舍：v1 的压缩/加密两组不迁移**。v2 任务表单明确不做 tar.xz 归档、
  口令是连接参数而非独立加密开关——照搬会出现两个"设置了也无效"的假开关。
  理由写在 `Setting.h` 类注释。
- 字段映射到 v2 真实存在的行为：自动接收失败重试（原硬编码 3 次 × 3 秒 →
  QSettings：autoRetry / retryInterval / retryMax，次数 0=一直重试）+
  接收覆盖开关（复用既有 `receiver/overwrite` 键，与日志右键菜单同步）。
- **新增 `app/ui/SettingsKeys.h`：QSettings 键单一来源**。原来 connector/*、
  receiver/* 键以字符串字面量散在 4 个文件里，改名必漏。全部消费方
  （MainWindow/ConnectorControl/LogControl/CoreService）已改用常量。
- MainWindow 重试逻辑消费配置；关闭重试或次数用尽后停手，日志给可执行指引。

### 2. ReplaceArea 作用域（c118c06）

- **考古发现：v1 的对话框本身也有假选项**——`ReplcaeResult.useCase/useRegex`
  传进了 v1 ComparisonControl 的替换 lambda 但从未使用，实际恒为区分大小写
  普通替换；只有作用列勾选真正生效。
- v2：作用列对齐行模型四字段（名称/本地目录/对端/相对目录，v1 是名称/本地/远端）；
  useCase（Qt::CaseSensitivity）与 useRegex（QRegularExpression，pattern 先
  验证再替换）**做成真的**。
- 非正则命中计数自己数（QString::replace 不返回次数），注意 qsizetype。
- 删除了原 onReplace 里的 type 重推导循环（type 由 mark 推导，mark 不被
  替换，该循环是 no-op）。

### 3. ProgressTracker（32500f6，清单 #11）

- 新增 `app/model/ProgressTracker.{h,cpp}`：每个传输项 reset() 一次，进度
  回调喂 update()，返回 "35.2% · 1.2MiB/s" 直接渲染。
- 边界闭环：bytesTotal==0 → "--"（空文件/等请求占位）；bytesPerSecond<=0 →
  自算平均速度；**开始 200ms 内均值不可信 → 显示 "-"**（分母太小，首块读盘
  抖动会让均值虚高一个数量级）。
- 任务表进度列 70 → 150 宽度。`humanBytes` 原在 MainWindow 与
  RelayTaskControl 各有一份拷贝，收拢到 ProgressTracker.h（relayer::app）。
