## 现场：用户报"两个客户端在线列表显示 4 个"

用户 A、B 连同一个中继，刷新在线列表看到 4 条，问"是不是文件传输端也显示了"。

第一轮我判断是旧 exe（本地 `build/` 是 pull 之前的产物），让用户换
`build/bin/relayer.exe`。用户回"搞错了，我刚手动 git pull 了"——**是我搞错了**：
他的代码刚拉到最新，问题在新代码上也存在。我用最新代码实测（中继 + 两个
`relayerd` 客户端 + `list`），拿到 **5 条**：`client-5`（list 自己）、`nodeA`、
`nodeA~d`、`nodeB`、`nodeB~d`。用户看到的 4 条就是 2 人 × 2 条连接。

## 根因：命名约定前后缀不一致

`DESIGN.md §3.3` 承诺数据连接"不出现在在线列表里"，服务端也**确实**在
`Server::handleLocal` 里过滤（`isInternalPeerId`）。但：

- 数据连接 id 由 `cli/src/Client.cpp` 的 `dataIdFor` 拼成 `<控制连接 id>~d`
  ——**后缀**；
- `isInternalPeerId` 判 `id.front() == kInternalIdPrefix.front()`
  ——**前缀**。

两条规则永不相交，过滤恒为 false。常量名 `kInternalIdPrefix`、`PeerTable.h`
注释、`Server.cpp` 注释、`PROTOCOL.md §11.7` 全都写着"前缀"，所以读代码看不出
矛盾——**唯一能发现真相的地方是 `dataIdFor` 里那一行字符串拼接**。

`isInternalPeerId` 此前**零覆盖**：`tests/` 里一次都没引用过，e2e 也没断言过
列表内容。所以它和 `49401d5` 修掉的"列表应答不回显请求号"一样，属于"没有
用例覆盖的路径"。

## 修法：对齐判定函数，不改名字

`<ctrl>~d` 这个名字在对端协商、重连缓存、DESIGN §3.3 里都被引用为既定事实，
改名字要同步更多地方。所以：

- `kInternalIdPrefix`("~") → `kInternalIdSuffix`("~d")，判**后缀**；
- 同步 `PeerTable.h` / `PeerTable.cpp` / `Server.cpp` / `cli/src/Client.cpp`
  的注释，`PROTOCOL.md §11.7` 与 `DESIGN.md §3.3` 的表述（并在协议里写明
  "标记落在末尾，不是开头"以及当初按前缀判的后果）；
- `tests/core/PeerTableTest.cpp` 新增 2 个用例（真实形状、`d` 结尾的控制连接
  名、`~d` 在中间/只有一半的反例）；
- `tests/e2e/run_e2e.py` 新增 `online-list` 场景。

用户："很期望具体的传输过程像 v1 一样有一个单独的弹窗"。v2 迁移时把

改法（提交 `d571b95`，已推送）：

  就是顶层窗口。保留 parent=MainWindow（随主窗口销毁），默认隐藏，

## 布局两连修（734ffa1）

1. **sTop 启动空洞 137px**：QSplitter 初始布局按子控件 sizeHint 累加定位，
   实际几何被 maximumWidth 钳小——ConnectorControl sizeHint≈487 > max 350，
   QTabWidget 起点仍按 487 算，差值成空洞；拖一下分割器重算 sizes 就贴合，
   所以"只有刚启动有问题"。修法：ConnectorControl::sizeHint() 自钳到 max。
2. **任务对话框默认尺寸盖住分页行**：显式 setMinimumSize(720,320) 覆盖了
   minimumSizeHint（Qt 规则），布局真实最小值（宽 958+，随字体/DPI 变）
   被掩盖，窗口可开到比内容小。修法：删显式 min，保留 resize(960,460)。

**教训**：离屏跑不出这两个现象——offscreen 字体度量与真实平台不同，
sizeHint 恰好 ≤350 所以贴合。布局类问题必须在目标平台验证；临时探针用
`move(-32000,0)` 挪出屏幕 + env 开关，测完删除。
