### 新旧配置的实质差异

| 项 | 旧 | 新 |
| --- | --- | --- |
| ColumnLimit | 120 | 130 |
| PointerAlignment | Right | Left |
| BreakBeforeBraces | Allman | Custom（只 AfterFunction/AfterClass） |
| AllowShortFunctionsOnASingleLine | Empty | None |
| SpacesBeforeTrailingComments | 2 | 3 |
| include 分组 | 4 组（自身头/C 库/三方/本项目） | 2 组（`<>` / `""`） |
| Standard | c++17 | 未设 → Latest |

include 压成两组后，`<asio/...>`、`<fmt/...>` 会与 `<vector>` 混排按字典序。
旧配置专门给三方库留了 Priority 3，新配置没有——**这是有意的取舍还是漏了，
下次问到再说**，别自己改回去。

`SpacesBeforeTrailingComments: 3` 让 `}  // namespace x` 变成三空格。

### 验证方法（值得复用）

纯格式改动的正确验证不是"看一眼 diff"，而是**去掉全部空白后逐文件比对**：

```python
a = re.sub(rb'\s+', b'', git_show_HEAD(f))
b = re.sub(rb'\s+', b'', open(f,'rb').read())
```

结果：91 个文件完全相同，41 个只差 include 顺序（去掉 `#include` 行后
完全一致），**0 个有其它差异**。再加跑两遍 clang-format 比 md5 验幂等，
最后 Debug 与 Release(-Werror) 各 ctest 7/7。

做完这三步才能说"只是格式改动"。

### 踩到的两件事

1. **`.clang-format` 带 UTF-8 BOM**（`ef bb bf`）。clang-format 22 能读，
   `--dump-config` 显示各项都生效了，所以没改用户的文件。但别的工具
   （editorconfig 检查、某些 CI 脚本）不一定吃 BOM，值得提一句。
2. **`build/` 又被留成 `RELAYER_BUILD_TESTS=OFF`**，`ctest` 直接报
   "No tests were found"。这是记忆里记过的同一个坑（另一次是 GUI=OFF），
   已重新 configure 回 ON。**在 build/ 里看到 ctest 说"没有测试"，先查
   CMakeCache，不要怀疑测试写坏了。**

### 行尾

工作区大半是 CRLF、少数几个是 LF（用户编辑器不一致），但 `.gitattributes`
是 `* text=auto eol=lf`，索引里一律 LF，所以提交 diff 没有行尾噪音。
clang-format 默认 `LineEnding: DeriveLF`（沿用文件原样），不主动改行尾。
`git add` 时那些 "CRLF will be replaced by LF" 的 warning 是正常的，
不用管。
