## 远端列表修改时间全是 1970（提交 41d3b9b）

用户报：浏览远端目录，修改日期都是 1970。

排查链路：协议（§11.8）带 `i64 mtime`，decode → `RemoteEntry` → GUI
`r.mtime * 1000` 全都在用，**唯独源头没填**：`StdFileStore::list` 的
`emit` 只填 name/isDir/size。`stat()` 里倒是有正确的换算。

修复：
- 抽 `toUnixTime()`（C++17 file_time_type 纪元未标准化，MSVC=1601、
  libstdc++=2174，用 duration 差值法换算），stat 与 list 共用
- 目录也填 mtime；单条取不到就留 0，别让一条失败丢整个列表
- 回归测试「list 返回每个条目的修改时间」——**此前没有任何用例断言过
  list 的 mtime，这就是漏掉的原因**。教训：IFileStore 接口的每个字段
  至少要有一个用例碰过，否则实现者会默认"没测=不重要"

## 取消共享根 + 发送前覆盖提示（提交 189e869）

用户先问"为啥会有阻塞 IO 弹窗超时上限"，然后给了正确方案：**把所有要验证
的内容一次性发给对方，弹等待窗口，拿结果逐项询问（或全是/全否）**；同时
要求取消共享根、像 v1 一样全路径访问。

### 为什么"传输中弹窗"是错的（这条别再犯）

决策点在 `TransferPeer::handleSendRequest`，跑在 io 线程，`kAnswerSend`
压在那里。弹窗等用户点按钮期间心跳也停（空闲 20s 发 ping、10s 未答判死），
中继会把连接踢掉。所以只能加"用户没点就超时"的兜底 —— 比不弹更糟。
**凡是需要用户决策的事，一律挪到传输开始之前。**

### 落地

- 新帧 138/139 `kAskPathMeta`/`kAnswerPathMeta`：一次往返查一批绝对路径的
  存在/大小/mtime/quickFingerprint。应答按**下标**对应请求，不重复路径。
- 发送前：按对端分组 → 每对端一次请求 → 逐项弹「覆盖/全部覆盖/跳过/
  全部跳过」，关窗=取消整批，默认按钮是「跳过」。
- 内容粗判直接用 desc 里现成的 quickFingerprint 语义，省掉 v1 那轮
  AskFileSamplesBatch。
- 接收端回到 v1 语义：**总是覆盖**。设定里「覆盖已有」→「发送前检查」。

### 全路径

- 列举/取回/打包/发送落点全部绝对路径；路径长度前缀 u8 → **u16**（绝对
  路径轻松超 255）。
- 空路径 = 根列表（`IFileStore::roots()`）：Windows 盘符 + 家目录，Unix
  `/` + 家目录。根列表条目名是完整路径，靠应答头 flags.bit0 显式标记，
  **不靠"名字里有没有分隔符"猜**（否则对端发 `../../etc` 就绕过单段校验）。
- `TransferDesc::root` 绝对路径 = 直接落那里，不做 resolveWithin。
- 踩到一处老代码：行级下载会 `while (rel.startsWith('/')) rel.remove(0,1)`
  ——那是相对路径时代的残留，会把绝对路径打成相对的。
- 代价写进 PROTOCOL §11.8.1：中继上知道本机 id 的人可读本机任意路径。
  不是疏漏，是取舍；要恢复沙箱得先恢复共享根。

## 路径显示规范化（提交 17ed4fd）

用户报界面出现 `D://Download`。根因：拼接时只把 `/` 当分隔符，而根列表
给的盘符根是 `D:/` 形式，再补一个 `/` 就成 `D://Download`。

规则收敛成一份 `core/session/PathText`（Qt 无关 + 单测），`app/model/PathText.h`
只做 QString 包装：**内部一律 `/`**，需要本地落盘/显示时才转 native（v1 的
约定）。接了六个地方：浏览面板（进入/双击/上一级/根列表显示）、MainWindow
（发送目标、行级下载）、RelayTaskControl（目录展开）、ComparisonControl
（列输入与配置载入）、CLI 应答侧入口、`IFileStore::roots()` 输出 `C:/`。

教训：**同一个路径字符串在三个地方各拼一次，必然有三种边界处理**。
`RelayTaskControl` 里的 `relDir + "/" + name` 就是第二处同类 bug——我第一轮
只修了 `joinAbs`，漏了它。以后凡是"拼路径"都走 joinRemotePath。

结果是"发到对方接收目录"这种最常见用法的发送前检查恒报"不存在"。加了

## 浏览面板：右键菜单合回一套（v1 的形状）

动作表"的结构，改成一张表、每项带**两个执行体**：

```cpp
add(visible, label, localFn, remoteFn);   // 为空的 = 这一端不支持，自动隐藏
```

`source_` 只决定"谁去执行"，不决定"显示哪些项"。目前按端隐藏的只有两项：

删除、SHA256（远端请对端算）、粗校验、时间戳校验、解压缩、复制全路径、
详细信息、刷新（本地原本没有这一项）。

粗校验/时间戳校验之所以能两端共用同一段逻辑：结论与方向无关——都是
"本地目录/name vs 远端目录/name"，`MainWindow::onCompareRequested` 本来
就同时取两个面板的当前目录。

坑：`add` 里如果给两端传**同一个** std::function 变量，一次 move 之后另一个
就空了。两端逻辑相同要写字面量两份。

### 踩到的坑
